# S8 Attempt 03 RCA

- Status: rejected; zero acceptance and soak credit.
- Source revision: `7af5aede866c78ed3ecdd42c41ec159e3e8bee5b`.
- Passed before stop: 15 independent fault repetitions (control, latency,
  transient, retry-budget, and poison; three each).
- Stop point: timeout repetition 1.

## Observed Failure

Six tasks were admitted. Four healthy tasks completed, while two intentionally
delayed submissions remained `outcome_unknown` at the 120-second drain boundary.
No duplicate logical effect occurred, but only four unique effects existed, the
two ambiguous task traces did not satisfy the full success chain, and the final
PostgreSQL-to-JSON mirror could not converge before the run stopped. Isolated
schema, process, listener, and monitoring cleanup completed.

## Root Cause

The queue worker execution timeout and the Airflow HTTP request timeout were both
10 seconds. The worker terminated its executor at the same boundary where the
HTTP client should have returned control to effect reconciliation. The durable
effect row was therefore already `submitting`, so retry correctly failed closed
to `outcome_unknown`. The S8 runner was also wrong to expect a successful effect
from an intentionally ambiguous timeout.

## Remediation

The v4 experiment contract preserves the existing fail-closed store behavior and
changes only the isolated S8 contract:

- a 30-second bounded outcome-observation window fits beneath the frozen
  60-second MTTR guardrail;
- timeout tasks must close as explicit `failed` with
  `external_effect_not_found_after_timeout` when exact effect lookup remains
  empty;
- timeout tasks require the timeout failure trace subset and exactly zero
  external effects;
- healthy tasks behind the timeout must complete, and queue/outcome/mirror state
  must fully drain.

All 21 fault repetitions restart from a clean v4 revision. None of the 15 earlier
passes are carried into acceptance.

## Claim Boundary

This is controlled failure evidence on one local physical node. It does not prove
customer production SLA, physical-node failover, HA/DR, or multi-node behavior.
