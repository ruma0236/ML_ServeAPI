## Observed Failure

The first two no-fault control repetitions completed through the external task
API, PostgreSQL durable queue, real queue-worker process, deterministic
dependency fixture, Prometheus, and OTLP. Each accepted eight tasks, reached
eight terminal completions, produced eight unique external effects, recorded
zero duplicate effects, completed every trace chain, and cleaned the isolated
schema and processes.

The third control repetition failed before workload admission. A host port was
reported free, then became occupied before Docker bound the isolated Prometheus
container. Docker rejected the bind. The repetition was retained as failed,
its isolated schema and process tree were removed, later fault profiles were
not started, and the soak gate remained closed.

## Root Cause And Remediation

This is a time-of-check/time-of-use collision in isolated Prometheus host-port
allocation, not an accepted workload guard failure. The shared S2 helper now
retries only the two explicit Docker port-collision error classes, selects a
new ephemeral port for each try, caps attempts at three, and preserves every
other Docker startup error as an immediate fail-closed result. A focused
regression fixes the collision behavior.

The complete seven-profile by three-repetition fault matrix will restart from
a clean remediation revision. No result from this attempt can be mixed into
the accepted matrix.
