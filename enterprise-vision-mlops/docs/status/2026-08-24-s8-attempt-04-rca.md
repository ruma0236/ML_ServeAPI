# S8 Attempt 04 MTTR Projection RCA

- Status: rejected acceptance attempt; zero credit.
- Source revision: `75f07559e58d84ba3fd9c65f1bbf3c4f5867e00f`.
- Fault matrix: `21/21` individual scopes passed.
- Soak: not started.

## Result

All seven fault profiles completed three clean independent repetitions. Every
scope passed terminal identity closure, exact effect accounting, trace checks,
PostgreSQL/JSON mirror parity, Prometheus checks, and deterministic cleanup.
Aggregate fault admission still failed because the maximum projected MTTR was
`63.234 s` against the frozen `60 s` bound.

The three worker-loss scopes reported `61.608 s`, `63.188 s`, and `63.234 s`.
Timeout scopes reported `51.204-51.704 s`; retry-budget recovery stayed below
`42.859 s`. Duplicate effects and pool timeouts were zero.

## Root Cause

`fault_recovery_elapsed_seconds` measured the entire worker-loss profile. That
profile intentionally contains two sequential experiments: first, exact worker
PID termination and recovery of a leased slow task; second, an independent
timeout-plus-healthy HOL check. The aggregate MTTR calculation therefore charged
the second validation phase to worker recovery. This is not the operational
worker MTTR boundary and made the three otherwise successful scopes fail the
aggregate gate.

## Remediation

V6 retains full profile elapsed for audit but adds a monotonic
`worker_recovery_elapsed_seconds` from exact PID failure to the reclaimed slow
task terminal outcome. Aggregate MTTR selects this profile-specific value for
worker-loss and retains full fault-to-terminal elapsed for the dependency fault
profiles. The metric basis is published and mutation-tested. The `60 s` bound is
not changed.

The full `21`-repetition fault matrix must restart from a clean v6 revision; the
three 30-minute soak repetitions remain gated.

## Boundary

This is controlled single-local-node failure evidence only. It is not production
SLA, HA/DR, physical-node failover, or multi-node evidence.
