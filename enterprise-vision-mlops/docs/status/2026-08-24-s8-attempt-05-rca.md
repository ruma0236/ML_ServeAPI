# S8 Attempt 05 Resource Sampler RCA

- Status: rejected acceptance attempt; zero credit.
- Source revision: `9c0d23488d7135884d38f6275b0b8d0525ad932d`.
- Fault matrix: `21/21` individual scopes passed.
- Soak: repetition 1 reached the end of its 30-minute measurement window but was invalidated; repetitions 2 and 3 did not start.

## Result

The complete V6 dependency-fault matrix passed with bounded retry amplification,
zero duplicate effects, bounded MTTR, trace closure, PostgreSQL/JSON parity, and
deterministic cleanup. Soak repetition 1 then ran at the frozen `35 RPS` load.
The point was rejected with no acceptance credit because the resource sampler
raised a `ReadTimeout` while reading the API metrics endpoint with a one-second
timeout. The exception was retained until the measured load phase completed,
then invalidated the point. No resource samples or load summary were accepted.

Private evidence contains `263` artifacts with aggregate SHA-256
`9cae37b8bdc325443784c46d832233a3e6a0ed6805452c515d38d036414baa66`.
The isolated API, Prometheus container, and marker processes were cleaned up.

## Root Cause

`collect_resource_samples()` delegated each metrics read to
`capacity_runtime_gauges()`. That function used a fixed one-second timeout and
did not convert a transient scrape failure into an explicit bounded sampling
outcome. A single timeout therefore terminated the sampler task. Because the
load phase and sampler are joined at the end of measurement, the failure was
only surfaced after the full 30-minute window.

This was an evidence-runtime robustness defect, not evidence that the accepted
service SLO passed or failed. The run remains permanently zero-credit.

## Remediation

The resource sampler will record each metrics-read failure, retain independently
collected host and process samples, tolerate only a bounded missing-sample ratio,
and fail closed after three consecutive metrics failures. Queue and pool slopes
will use only samples with valid runtime gauges, while RSS, handle, CPU, and
artifact slopes continue to use their actual samples. A short non-credit load
will prove transient recovery and repeated-failure stop behavior before the
complete `21 + 3 soak` suite restarts from a clean revision.

The `35 RPS`, latency/error bounds, 30-minute measurement duration, and three
accepted repetitions are unchanged.

## Boundary

This is controlled single-local-node evidence only. It is not production SLA,
HA/DR, physical-node failover, multi-node, multi-GPU, or customer-traffic
evidence.
