# R7s5 local-code closure contract

## Authority and scope

This contract implements the user's 2026-09-09 instruction authorizing a minimal R7-specific schema/writer/validator and automatic progression through R7-M15, then runtime-free R8-M00. That authorization is NOT test success or reviewer sign-off.

The controlling R7 micro-plan is M03/M04/M05/M09/M12 actual evidence -> M13 aggregate -> M15 closure. Its local execution profile is the observed pinned Windows/CUDA/private-data, real-PostgreSQL, host-interpreter and isolated Linux lanes, with a clean fresh candidate checkout. All required node/environment coverage is retained.

`ci/pre-r8-r7s5-test-lanes.json` remains the fail-closed contract for the separate externally-attested CI profile. It began as reviewer-pending/non-credit scaffolding (b98b555; amended9dfddc7); the active workflow is still unconnected. No approved source inspected makes its unimplemented external adapter the authority for the original local M13 aggregate. Therefore this local-code closure does not claim formal-CI PASS and does not consume its unavailable public adapter. This is profile/authority separation, not an exemption of required tests. Existing CI mutation/rejection tests remain mandatory product regressions.

Production OOB/WORM/admission, WSL detached residual, fencing, successor, ETW and dual collector qualification remain R8 tasks. Their NOT_RUN state does not invalidate an otherwise complete R7 local-code closure, and R7 GO does not make them PASS.

## Required evidence

- Exact code commit and tree obtained from Git, clean tracked/index state, a clean exact fresh checkout, complete source inventory and pinned dependency/tool provenance.
- Pinned static command results and current dynamic node collections; focused, general, host, real-PG, Linux portable/inverse and required private-data coverage.
- Raw stdout/stderr/JUnit, actual exit codes, exact unique node sets and governed skip identities. A skip earns no PASS credit. Every required union node must have actual PASS in a correct lane; subsets/overlaps are not added twice.
- Required private input hashes before/after the general run. Private subset need not be run twice when the general run actually executes it.
- Actual original elevated two-node execution with same-run independent OS process/token observation and M12 review bound to this candidate. Mocked lineage is not live provenance.
- Code/tool/manifest equality before and after execution, timeout/recovery/postcondition evidence and complete cleanup for the owned run resources.
- Separate source-local independent review of the frozen evidence and deterministic validator assessment, followed by final publication read-back.

Previous aggregate files whose GLOBAL decision is NO-GO supply history/inventory only. They are not relabelled as PASS. Required gate receipts/raw evidence are read and validated directly.

## Identity and freshness

Per-run artifacts bind code commit/tree, exact source/tool hashes, fresh checkout and run identity. No current-candidate pin is committed inside its own code artifact. Code commit, handoff/approval evidence and later closure commit remain distinct identities.

A changed source tree invalidates previous whole-tree regression credit. The original failed runs and consumed capsule IDs are immutable and never replayed. New runs use new output/attempt identities, with existing runners rather than a new generic supervisor.

Expected node collections and governed skips are frozen from the current candidate before test execution. Receipt/hash/collection mismatch, failure/error, unexpected skip/deselect, missing or duplicate node, stale candidate/tool/input and incomplete receipt reject local GO. No historical numeric total is hardcoded as the target.

## Reviewer boundary

Producer and reviewer roles must be distinct actual work/process instances, with their identifiers and measured provenance preserved. Reusing the same pinned executable is permitted; different executable hashes are not a condition of independence.

The frozen input manifest excludes the later reviewer hash. The reviewer artifact follows and binds manifest SHA, deterministic validation SHA, candidate commit/tree and reviewed evidence. The writer receives its expected SHA independently from the reviewed handoff, not from a caller-controlled field inside the input manifest.

This is the established procedural source-local independent-review boundary, not cryptographic external signer authentication. A different reviewer name string alone proves nothing. The author must not create their own passed review. Actual review records and observed provenance are required; fixture/mock/implementation-approval records earn zero acceptance credit.

## Writer boundary

Implement only R7-local functions and a small CLI. Preserve all legacy NO-GO and R8/production guards. Use existing canonical serialization, durable handle-bound no-replace publication and append-only hash-ledger mechanics; do not create new signing systems or a generic evidence framework.

Validate all inputs before publishing. Reject missing review, invalid hashes, other candidate, expired/stale data and duplicate publication. Persist deterministic candidate/run reservation and immutable report/seal/manifest/index, preserve partial/failure output, do not retry automatically, then re-open and validate the published output.

The result may state `r7s5_decision=GO` for local-code closure only. It must retain production/admission/externally-attested-CI authority=false and R8 operational NOT_RUN. The X1 ledger transition is `ready`/`non_credit` with an explicit R7 code-closure event, not X1/V4 `verified` or operational acceptance credit. The existing ledger chain is verified, then a new event binds the new code and closure evidence; historical chain PASS is insufficient.

## Cleanup and progression

Separate process, container and filesystem residue. Preserve user/untracked files, business data and raw evidence. Inventoried disposable basetemps remain residue until genuinely recovered; renaming or declaring them evidence is not cleanup.

Do not follow reparse points outside owned roots, repeat a policy-denied operation through another interpreter, alter ACL/security settings to evade policy, restart Docker/WSL or prune unrelated resources. If an operator/policy input is necessary, record exact targets and continue independent implementation/regression work.

Only after actual required tests, review, cleanup and publication read-back pass: perform normal push/read-back and existing evidence/index/seal/ledger/Jira/Notion/Obsidian updates, distinguish code from closure commits, and verify all claimed external writes.

R8-M00 then performs read-only gate inventory. R8-M01 onward qualification, ETW, fault injection and V4 experiments are not authorized by this contract.

## Required rejection regressions

Missing gate/result/raw file; corrupted/swapped/deleted artifact; wrong candidate/tree; stale time or changed tool/source; unexpected skip/deselect/error; duplicate/missing node; absent/self/mismatched reviewer; forged inline review pin; nonzero residue; duplicate publication; unsafe output path; partial publication/read-back mismatch. Fixture passes validate the tool only and never count as actual R7 execution.
